## Form Sections (13 sections)

### 01 · Patient Info
Shared FormBase fields. No change from established pattern.

### 02 · Diagnosis
- `diagnosis` — textarea (required)
- `management.type` — select: `Conservative | Surgical | Corticosteroid Injection | Medication + PT`
- `management.surgeryDate` — date input, reveals only when Surgical selected
- `problem` — textarea

### 03 · Hand Chart ★ NEW
- `dominant_hand` — radio L / R (required)
- Right hand SVG `#hand-svg-r` (palmar view) + Left hand SVG `#hand-svg-l` (palmar view) — side by side
- Pain type selector `#hctype-sel` (same types as bodychart: ache/sharp/numb/burn/refer/tender)
- Marker list `#hand-marker-list` — shows both hands' markers
- `handChart.notes` — textarea below the chart for additional notes

### 04 · Pain Score
- `pain.pre` / `pain.post` — VAS sliders 0–10
- `pain.nature` — chips: `Dull · Sharp · Tingling · Burning · Throbbing`
- `pain.agg` — chips: `Gripping · Typing · Repetitive movements · Prolonged use · Lying on arm`
- `pain.ease` — chips: `Rest · Splinting · Ice · Neutral wrist`
- `pain.behaviour24` — chips: `Night dominant · Morning stiffness · End-of-day fatigue`
- `pain.irritability` — radio: `High · Medium · Low`
- `pain.splinting` — radio: `Yes · No` (HAND-specific field)

### 05 · Special Questions
- `sq.generalHealth` — **select dropdown**: `Well/Afebrile · Unwell/Febrile · Other`  
  When `Other` selected: `sq.generalHealthNotes` textarea reveals
- `sq.pmhxSurgery` — textarea
- `sq.investigations` — textarea
- `sq.medicationSteroids` — textarea
- `sq.homeSocial` — textarea
- `sq.occupationRecreation` — textarea

### 06 · History
- `hx.current` — textarea
- `hx.past` — textarea

### 07 · Observation
- `obs.chips` — chips (multi-select): `Swelling · Thenar wasting · Hypothenar wasting · Claw deformity · Incomplete grip · Scarring · Contracture · Psoriasis · Clumsy fine motor`
- `obs.notes` — textarea + `ClinicalTemplates.addButton('obs-notes', 'HAND_OBS')`

### 08 · Palpation
- `palp.chips` — chips (multi-select): `Normal · Tenderness · Soft swelling · Thickened tendon · Triggering · Crepitus · Tight scar · Warmth · Wrist malalignment`
- `palp.notes` — textarea + `ClinicalTemplates.addButton('palp-notes', 'HAND_PALP')`

### 09 · Physical Exam — ROM Table
Static HTML `<table>` (NOT movement_table.js — rows are fixed, not dynamic).

Columns: `Movement | Active L | Active R | Passive L | Passive R | Overpressure L | Overpressure R`  
All cells are `<input type="number">`. Blank = not tested.

Rows (~25):
- Finger MCP Flex/Ext × Index, Middle, Ring, Little
- Finger PIP Flex/Ext × Index, Middle, Ring, Little
- Finger DIP Flex/Ext × Index, Middle, Ring, Little
- TAM / TPM × Index, Middle, Ring, Little
- Thumb MCP Flex/Ext
- Thumb IP Flex/Ext
- Wrist Flex · Ext · Radial Dev · Ulnar Dev
- Elbow Flex · Ext
- Forearm Pro · Sup

Collect: `rom.table` = array of `{movement, activeL, activeR, passiveL, passiveR, opL, opR}`. Skip rows where all 6 values are blank.

### 10 · Strength + Circumference
**Strength:**
- `strength.gripR` / `strength.gripL` — number inputs (kg)
- `strength.pinchLateralR/L` — number inputs
- `strength.pinchPulpR/L` — number inputs
- `strength.pinch3ptR/L` — number inputs
- `strength.pulpPulpOpposition` — checkbox
- `strength.finger2Crease` / `strength.finger3Crease` / `strength.finger4Crease` / `strength.finger5Crease` — checkboxes (finger-to-palmar crease)

**Circumference (all optional):**
- Per finger (Index/Middle/Ring/Little/Thumb) × PIP/DIP × L/R — number inputs (cm)
- Palmar crease L/R — number inputs
- Wrist L/R — number inputs

Collect: `circumference.table` = array, only include cells with values.

### 11 · Sensation + Other Tests
- `sensation.notes` — textarea (Semmes-Weinstein / light touch, too variable to chip)

**Other Tests — structured chips:**  
For each test: `Tinel's · Phalen's · Finkelstein's · Froment's · Grip strength`  
Per test: R = `Pos / Neg / NT` (radio/chip toggle) + L = `Pos / Neg / NT`

Collect: `otherTests = { tinels: {r, l}, phalens: {r, l}, finkelsteins: {r, l}, fromens: {r, l}, gripStrength: {r, l} }`

### 12 · Neurology
**Reflexes** — per reflex: `C5 Biceps · C6 Brachioradialis · C7 Triceps · C8/T1`  
Each: L and R selects with options `A (Absent) · N (Normal) · B (Brisk)`

**Muscle Grades** — per muscle: `Deltoid · Biceps · Wrist Extensors · Wrist Flexors · Finger MP Ext · Triceps · Finger Flexion · Hand Intrinsics`  
Each: L and R selects 0–5

Collect: `neuro = { reflexes: {c5: {l,r}, c6: {l,r}, c7: {l,r}, c8t1: {l,r}}, muscles: {deltoid: {l,r}, ...} }`

### 13 · PT Impression + Goals + Plan
- `pt_impression` — textarea (required) + `ClinicalTemplates.addButton('pt-impression', 'HAND_IMPRESSION')`
- `plan.stg` — textarea + `ClinicalTemplates.addButton('plan-stg', 'HAND_STG')`
- `plan.ltg` — textarea + `ClinicalTemplates.addButton('plan-ltg', 'HAND_LTG')`
- `plan.treatment` — textarea + `ClinicalTemplates.addButton('plan-treatment', 'HAND_PLAN')`
- Sign & chop block (shared `sign_chop_block()` via base.html / rendered in PDF only)

## handchart.js — New IIFE

**Architecture:** Exact clone of `bodychart.js`. Replace `view` field with `hand` field ('R' or 'L'). Two SVGs instead of one.

```
Public API:
  HandChart.init()       — attach events to both SVGs + type selector
  HandChart.getData()    — returns markers[] array
  HandChart.loadData(arr) — load saved markers onto SVGs
  HandChart.clearAll()   — remove all markers from both SVGs

State:
  markers[] = { id, hand, type, x, y, el }
  hand = 'R' or 'L'

SVG IDs:
  #hand-svg-r    — right hand palmar SVG
  #hand-svg-l    — left hand palmar SVG
  #hctype-sel    — pain type selector (same as bodychart: ache/sharp/numb/burn/refer/tender)
  #hand-marker-list — shared list, grouped by hand
```

SVG viewBox for both: `0 0 200 280` (A4-proportional).

Marker rendering: `<g>` with colored `<circle r="8">` + `<text>` counter number, same as bodychart.

`main.js` auto-calls `HandChart.init()` when `#hand-svg-r` is detected in DOM (add to the existing BodyChart.init() auto-detection block in `init()`).

**Collect in form_hand.js:**
```javascript
handChart: { markers: HandChart.getData(), notes: gv('hand-chart-notes') }
```
**Populate:** `HandChart.loadData(d.handChart.markers)`  
**Reset:** `HandChart.clearAll()`

## pdf_hand.py

**Hand chart in PDF:**  
Use `BodyChartFlowable` pattern from `pdf_base.py` as reference — mirror exactly how bodychart renders into PDF today (confirm whether it converts the live SVG at PDF-generation time or uses an alternative approach; reuse the same mechanism for hand).

- **Source of truth:** the live SVGs in `handchart.js` (`#hand-svg-r`, `#hand-svg-l`). No pre-rendered PNG assets exist or are committed to the repo.
- **At PDF generation time:** render each hand SVG to an image (whatever conversion mechanism bodychart uses — likely `svglib` + `reportlab` or equivalent). Both right and left hand images generated dynamically per PDF.
- Loop over `handChart.markers`:
  - `hand == 'R'` → draw on the right-hand rendered image
  - `hand == 'L'` → draw on the left-hand rendered image
- Scale coordinates: `x_pdf = (m.x / 200) * img_width_pts`, `y_pdf = (m.y / 280) * img_height_pts`
- Draw ReportLab colored circle + type label at scaled position

**Layout:** Match the original KKM hand assessment form (`fisio / b.pen. 12 / Pind. 2 / 2019`) at minimum 90% visual fidelity. The printed PDF should look like the KKM borang — same section ordering, same field grouping, same overall flow. A clinician comparing the printed PDF side-by-side with the original KKM form should recognise it as the same form digitised.

2-column KKM borang layout. Split into 3–4 `two_col()` blocks to stay under 250mm per block. Within each block, mirror the KKM form's actual section ordering and field grouping, NOT a free-form rearrangement.

Rough block division (adjust per KKM form's real layout):
- Block 1: patient info + diagnosis + hand chart
- Block 2: pain score + special questions + history
- Block 3: observation + palpation + ROM table (full-width)
- Block 4: strength + circumference + sensation + other tests + neurology + impression/goals/plan

If any field grouping in the spec sections (01-13 above) conflicts with the KKM form's actual layout, the KKM form wins — flag the conflict before writing code.

**ROM table:** Full-width `Table` flowable with `Paragraph()` in cells. Blank cells = empty string. Skip rows where all values are blank.

**Footer:** `story += sign_chop_block()`
